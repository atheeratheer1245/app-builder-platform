# مخطط قالب الألعاب الاحترافي في App Builder

## الهدف

لا ينبغي أن يكون قالب اللعبة صفحة ثابتة فيها زر وصورة فقط. يجب أن يكون **مشروع لعبة قابلًا للتكوين**، ينشئ منه العميل نموذجًا قابلًا للعب عبر اختيار نمط اللعبة، ثم يربط المشاهد والشخصيات والقواعد والواجهات والوسائط. الفكرة الأساسية هي فصل ما يراه اللاعب، مثل المراحل والأزرار والنقاط، عن منطق اللعبة، مثل الحركة والتصادم والوقت وشروط الفوز.

> **المبدأ:** كل لعبة تتكون من مشاهد، وكل مشهد يحتوي على كائنات، وكل كائن يملك خصائص وأحداثًا وقواعد استجابة.

| طبقة القالب | وظيفتها | ما يضبطه العميل |
|---|---|---|
| نمط اللعبة | يجهز القواعد والمكونات المناسبة تلقائيًا | النوع، الاتجاه، وضع اللعب، مستوى الصعوبة |
| المشاهد | تنظّم تجربة اللاعب من البداية إلى النهاية | البداية، اللعب، الإيقاف، الفوز، الخسارة، المتجر |
| الكائنات | تمثل اللاعب والخصوم والعناصر والعوائق | الشكل، الحجم، الموضع، الفيزياء، العلامات |
| القواعد | تحدد ما يحدث عند التفاعل | التصادم، النقاط، الصحة، الوقت، الانتقال |
| واجهة اللاعب | تعرض المعلومات وتوفر التحكم | الأزرار، شريط الصحة، العدّاد، الرسائل |
| المحتوى | يجلب المواد البصرية والسمعية الفعلية | صور، فيديوهات، أصوات، موسيقى، خرائط |

## الأنماط التي ينبغي دعمها في المرحلة الأولى

يُفضّل أن يبدأ القالب بأنماط ثنائية الأبعاد ذات منطق واضح وإعادة استخدام مرتفعة، بدل محاولة بناء كل أنواع الألعاب ثلاثية الأبعاد دفعةً واحدة.

| النمط | نموذج مناسب | المكونات الأساسية | قواعد اللعب النموذجية |
|---|---|---|---|
| **المنصات** | قفز وجمع عملات | لاعب، أرضيات، منصات، عوائق، كاميرا جانبية | قفز، جاذبية، سقوط، جمع، وصول إلى النهاية |
| **الجري اللانهائي** | تفادي عوائق | لاعب، مسار متحرك، عوائق، عناصر مكافأة | حركة تلقائية، قفز أو انزلاق، زيادة سرعة، أعلى نتيجة |
| **الألغاز** | مطابقة أو سحب وإفلات | شبكة، قطع، خانات هدف، عداد حركات | مطابقة، تبديل، تحقق من الحل، عدد محاولات |
| **الأسئلة والاختبارات** | مسابقة تعليمية | سؤال، إجابات، مؤقت، نقاط، مستويات | إجابة صحيحة أو خاطئة، سلسلة إجابات، وقت متبقٍ |
| **الذاكرة والبطاقات** | مطابقة الأزواج | بطاقات قابلة للقلب، شبكة، عداد وقت | قلب بطاقتين، مطابقة، حفظ الحالة، إنهاء الجولة |
| **الدفاع عن المسار** | إيقاف موجات الخصوم | مسار، أبراج، خصوم، عملة، موجات | وضع برج، مدى هجوم، صحة الخصم، مكافآت |
| **التصويب البسيط** | سفينة أو هدف متحرك | لاعب، مقذوف، هدف، منطقة ظهور | إطلاق، إصابة، نقاط، صحة، إعادة ظهور |
| **السباق المبسط** | مركبة في مسار | مركبة، مسار، نقاط تحقق، منافس اختياري | تسارع، توجيه، لفة، وقت، تجاوز نقاط التحقق |
| **المحاكاة الخفيفة** | إدارة مقهى أو مزرعة | موارد، طلبات، ترقيات، عملة | إنتاج، انتظار، إنفاق، فتح عناصر، حفظ تقدم |

## المشاهد التي يحتاجها أي قالب لعبة متكامل

يجب أن يبدأ كل مشروع ألعاب بحزمة مشاهد جاهزة يمكن حذفها أو توسعتها. لا يضطر العميل إلى بنائها من الصفر كل مرة.

| المشهد | مكوّنات افتراضية | التفاعل المطلوب |
|---|---|---|
| شاشة البداية | شعار، خلفية، زر ابدأ، إعدادات، لغة | يبدأ اللعبة أو يفتح الإعدادات |
| اختيار المرحلة | بطاقات مراحل، حالة القفل، النجوم، زر رجوع | يفتح مرحلة متاحة فقط |
| اللعب | طبقة عالم اللعبة، واجهة HUD، تحكم، إيقاف | يطبق قواعد النمط المحدد |
| الإيقاف المؤقت | متابعة، إعادة، إعدادات، خروج | يحفظ حالة المرحلة مؤقتًا |
| الفوز | نتيجة، نجوم، مكافأة، التالي | يفتح المرحلة التالية أو يعيد للخريطة |
| الخسارة | سبب الخسارة، إعادة، رجوع | يعيد المرحلة دون كسر التقدم |
| النتائج | أعلى نتيجة، الوقت، إنجازات | يعرض الأداء ويحفظ الرقم الأفضل |
| المتجر والترقيات | رصيد، عناصر، معاينة، شراء | يطبق الشراء داخل منطق اللعبة فقط عند توفره |

## كتالوج مكوّنات القالب

### 1. مكوّنات العالم والكائنات

هذه هي القطع التي يضعها العميل داخل مشهد اللعب. يجب أن تظهر في لوحة طبقات حتى يتمكن من ترتيبها واختيارها وتكرارها وحذفها.

| المكوّن | خصائص يجب أن تظهر في المحرر | سلوك افتراضي |
|---|---|---|
| **لاعب** | صورة أو رسوم متحركة، سرعة، قفز، صحة، فريق، نقطة بداية | يستقبل التحكم ويستجيب للتصادم |
| **خصم** | صورة، صحة، سرعة، نمط حركة، ضرر، مكافأة | يتحرك أو يطارد أو يحرس منطقة |
| **عائق** | صورة، حجم، صلب أو ضار، ضرر | يمنع الحركة أو ينقص الصحة |
| **منصة أو أرض** | الحجم، الملمس، صلبة أو متحركة | تدعم اللاعب وتشارك في التصادم |
| **عنصر قابل للجمع** | صورة، قيمة نقاط أو عملة، صوت جمع | يختفي عند اللمس ويمنح مكافأة |
| **بوابة أو نقطة نهاية** | صفحة أو مرحلة الهدف، شرط الفتح | تنقل اللاعب بعد تحقق الشرط |
| **منطقة تفعيل** | شكل المنطقة، حدث الدخول والخروج | تشغل رسالة أو موجة أو انتقالًا |
| **نقطة ظهور** | نوع الكائن، عدد، توقيت، حد أقصى | تنشئ خصومًا أو عناصر بتسلسل |
| **كاميرا** | تتبع هدف، حدود، اهتزاز، تكبير | تتابع اللاعب أو تثبت على الخريطة |
| **خلفية وطبقات** | صورة أو فيديو، سرعة تحريك، تكرار | تضيف عمقًا بصريًا وبيئة للمرحلة |

### 2. مكوّنات التحكم وواجهة اللاعب

| المكوّن | الإعدادات | استخدامه |
|---|---|---|
| عصا تحكم افتراضية | موضع، حساسية، اتجاهات مسموحة | حركة اللاعب على الهاتف |
| أزرار حركة | أعلى، أسفل، يمين، يسار، قفز، إطلاق | بديل واضح لعصا التحكم |
| زر إجراء | نص أو أيقونة، الحدث المرتبط | فتح، تفاعل، إطلاق، استخدام عنصر |
| شريط صحة أو طاقة | قيمة قصوى، ألوان، موضع | عرض حالة اللاعب أو الخصم |
| عداد نقاط وعملة | بادئة، أيقونة، تنسيق | عرض التقدم والمكافآت |
| عداد وقت | تنازلي أو تصاعدي، شرط الصفر | سباق، اختبار، تحدي زمني |
| سجل مهام | قائمة أهداف، حالات الإنجاز | يوضح المطلوب داخل المرحلة |
| نافذة تعليمات | نص عربي وإنجليزي، زر فهمت | تشرح التحكم عند أول دخول |
| رسالة حدث | عنوان، وصف، صورة، زر متابعة | فوز، خسارة، اكتشاف، ترقية |

### 3. مكوّنات الوسائط

يجب أن يرتبط كل عنصر بملف حقيقي من معرض المشروع، وليس بنص أو رابط افتراضي. يدعم المحرر معاينة الملف قبل الحفظ ويمنع اختيار نوع ملف غير مناسب للمكوّن.

| نوع الوسيط | الاستخدام في اللعبة | الحقول المطلوبة |
|---|---|---|
| صورة | شخصيات، أزرار، خلفيات، عناصر، بطاقات | الملف، النص البديل، أبعاد العرض |
| رسوم متحركة | حركة لاعب وخصم وتأثيرات | إطارات أو ملف رسوم، سرعة، تكرار |
| فيديو | مقدمة، قصة قصيرة، إعلان مرحلة | الملف، التشغيل التلقائي، تخطي |
| مؤثر صوتي | قفز، اصطدام، جمع، فوز، خطأ | الملف، مستوى الصوت، حدث التشغيل |
| موسيقى | خلفية القائمة أو المرحلة | الملف، تكرار، مستوى الصوت |
| خط مخصص | عناوين اللعبة والنقاط | الملف، الوزن، الحجم، دعم العربية |

## نظام المنطق المرئي واللبنات البرمجية

بدل إلزام العميل بكتابة كود، يستخدم القالب **لبنات منطق** على شكل: حدث ← شرط ← فعل. يجب أن يستطيع العميل ترتيبها داخل كل كائن أو مشهد.

| الفئة | أمثلة لبنات يجب توفيرها |
|---|---|
| الأحداث | عند بدء المشهد، عند لمس كائن، عند ضغط زر، عند انتهاء المؤقت، عند جمع عنصر، عند هز الجهاز |
| الحركة | تحرك بمقدار، قفز، اندفع، اتبع هدفًا، اذهب إلى موضع، أوقف الحركة |
| الفيزياء | فعّل جاذبية، اجعل الكائن صلبًا، ارتد، طبق سرعة، تحقق من الأرض |
| الحالة | غيّر الصحة، أضف نقاطًا، أضف عملة، اضبط متغيرًا، زد مستوى الصعوبة |
| الشروط | إذا كانت الصحة صفرًا، إذا كان العدد أكبر من، إذا تحققت جميع الأهداف، إذا كان العنصر موجودًا |
| المشاهد | افتح مشهدًا، أعد المرحلة، أوقف اللعبة، احفظ التقدم، افتح المرحلة التالية |
| الصوت والصورة | شغّل صوتًا، أوقف موسيقى، أظهر تأثيرًا، اهتز الكاميرا، غيّر الرسوم المتحركة |
| البيانات | خزّن أعلى نتيجة، اقرأ مستوى مفتوح، احفظ إعداد الصوت، صفّر تقدم الاختبار |
| الشبكة لاحقًا | لوحة متصدرين، حفظ سحابي، دعوة صديق؛ تبقى معطلة حتى يتوفر خادمها |

### أمثلة منطق قصيرة

| الحالة | قاعدة بصيغة لبنات |
|---|---|
| جمع عملة | عند لمس اللاعب للعنصر ← أضف 10 نقاط ← شغّل صوت الجمع ← احذف العنصر |
| خسارة اللاعب | عند صحة اللاعب تساوي صفرًا ← أوقف التحكم ← افتح مشهد الخسارة |
| فتح بوابة | عند عدد العناصر المجمعة يساوي 3 ← فعّل البوابة ← اعرض رسالة «الطريق مفتوح» |
| زيادة صعوبة | عند مرور 30 ثانية ← زد سرعة الخصوم بنسبة 10% |
| سؤال صحيح | عند اختيار إجابة صحيحة ← أضف نقطة ← انتقل للسؤال التالي |

## البيانات والتقدم

لكي تكون اللعبة نموذجًا مكتملًا، تحتاج إلى بيانات محفوظة محليًا أو في حساب اللاعب بحسب الصلاحيات المتاحة.

| البيانات | أمثلة | قاعدة الحفظ |
|---|---|---|
| ملف اللاعب | الاسم، اللغة، الصورة، الإعدادات | يحفظ عند تعديل الحساب أو الإعدادات |
| تقدم المراحل | المراحل المفتوحة، النجوم، أفضل وقت | يحفظ عند الفوز فقط |
| نتائج اللعب | أعلى نقاط، محاولات، إنجازات | يحفظ في نهاية الجولة |
| اقتصاد اللعبة | عملة، عناصر مفتوحة، ترقيات | لا يعدّل إلا عبر قواعد موثقة |
| إعدادات الوصول | الصوت، الاهتزاز، حجم النص، وضع التحكم | يحفظ فور التعديل |

## أساسيات الجودة التي يجب أن تكون جزءًا من القالب

ينبغي أن يوفر القالب إعدادات تجعل اللعبة قابلة للعب على الهاتف من دون إعداد يدوي معقد.

| المحور | ما يطبقه القالب افتراضيًا |
|---|---|
| العربية والإنجليزية | نصوص ثنائية اللغة، اتجاه RTL وLTR، خطوط قابلة للقراءة |
| الهاتف | أزرار لمس كبيرة، منطقة آمنة، تخطيط عمودي أو أفقي محدد لكل نمط |
| الوصول | كتم الصوت، اهتزاز اختياري، تباين واضح، نص تعليمات، عدم الاعتماد على اللون فقط |
| الأداء | ضغط الوسائط، الحد من الكائنات المتحركة، تحميل المرحلة عند الحاجة |
| الاستقرار | حالة تحميل، حالة فشل وسيط، حفظ عند نهاية المرحلة، زر إعادة واضح |
| الاختبار | زر تشغيل المرحلة، محاكاة لمس، قائمة أخطاء القواعد غير المكتملة |

## نموذج القالب الافتراضي المقترح: «مغامرة المنصات»

يصلح هذا النموذج كنقطة بداية لأنه يوضح معظم المكونات القابلة لإعادة الاستخدام في ألعاب أخرى.

| المشهد | ما يحتويه | النتيجة المتوقعة |
|---|---|---|
| البداية | شعار، زر ابدأ، زر لغة، زر إعدادات، موسيقى | انتقال إلى اختيار المراحل |
| المرحلة 1 | لاعب، أرض، 3 عملات، عائق، بوابة، شريط صحة، زر قفز | جمع العملات ثم فتح البوابة |
| الفوز | نقاط، وقت، نجوم، زر التالي | حفظ التقدم وفتح مرحلة جديدة |
| الخسارة | سبب الخسارة، زر إعادة، زر خروج | إعادة المرحلة دون ضياع التقدم السابق |

## خارطة التنفيذ داخل App Builder

| الأولوية | ما يضاف للمحرر | النتيجة العملية |
|---|---|---|
| 1 | مشاهد اللعب، اللاعب، العائق، المنصة، العنصر القابل للجمع، الأزرار، النقاط، الصحة | نموذج منصات أو جري بسيط قابل للعب |
| 2 | الحقول الفعلية للصور والصوت والفيديو والرسوم المتحركة من معرض المشروع | لعبة بوسائط العميل الحقيقية |
| 3 | لبنات حدث/شرط/فعل، تصادم، متغيرات، مؤقت، انتقال مشاهد | قواعد اللعب قابلة للتكوين بلا كود |
| 4 | حزم الأنماط الجاهزة للألغاز والاختبارات والذاكرة والتصويب والسباق | إنشاء سريع لألعاب مختلفة من نفس المنصة |
| 5 | حفظ تقدم، أعلى نتيجة، إنجازات، اختبار على الهاتف، تحضير التصدير | نموذج جاهز للمراجعة والتصدير عند تفعيل خدمة البناء السحابي |

## قرار التصميم المقترح

أقترح بدء القالب الافتراضي بلعبة **منصات تعليمية ثنائية الأبعاد**: يختار العميل شخصية، يرفع صور الخلفية والصوت، يضيف منصات وعوائق وعناصر قابلة للجمع، ويحدد شرط نهاية المرحلة. بعد اكتمال هذا الأساس، تتحول الأنماط الأخرى إلى إعدادات ومكوّنات إضافية بدل بناء نظام جديد لكل لعبة.

بهذا يصبح قالب الألعاب أداة إنشاء فعلية: العميل يبني نموذجًا قابلًا للتشغيل، لا مجرد واجهات تصف لعبة.
