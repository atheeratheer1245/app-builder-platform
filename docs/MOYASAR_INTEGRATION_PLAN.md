# خطة ربط Moyasar لموقع App Builder

## نموذج الدفع المعتمد

سيستخدم الموقع **فاتورة Moyasar المستضافة**. ينشئ الخادم فاتورة لقيمة طلب التصدير ثم يعيد رابط الفاتورة للمستخدم. لا تجمع المنصة بيانات البطاقة، ولا تعتمد تغيّر حالة التصدير إلا بعد استرجاع الفاتورة من Moyasar والتحقق من قيمتها وعملتها وحالتها.

| العنصر | القرار |
|---|---|
| بيئة البداية | الاختبار فقط باستخدام مفتاح يبدأ بـ `sk_test_` |
| إنشاء الدفع | `POST /invoices` من الخادم مع `amount` بالهللات و`currency: SAR` ووصف ورابط نجاح ورابط رجوع وcallback خادمي |
| واجهة العميل | تحويل المستخدم إلى رابط الفاتورة المستضافة الذي تعيده Moyasar |
| إثبات السداد | استرجاع الفاتورة من `GET /invoices/:id` والتحقق من `status: paid` والمبلغ والعملة قبل وضع التصدير في قائمة البناء |
| البيانات الحساسة | مفتاح Moyasar السري على الخادم فقط؛ لا تضعه في React أو في المستودع |
| الإنتاج | لا يستخدم مفتاح `sk_live_` إلا بعد تفعيل حساب Moyasar واختبار السيناريو الكامل |

## المتطلبات من مالك الحساب

المطلوب حاليًا هو **مفتاح Moyasar السري للاختبار فقط** (`sk_test_...`). يحصل عليه مالك الحساب من لوحة Moyasar ضمن إعدادات مفاتيح API. لا نحتاج المفتاح العام للفاتورة المستضافة، ولا نحتاج أي بيانات بطاقة من العميل.

> بعد إنشاء المفتاح السري، انسخه فورًا إلى حقل الأسرار المخصص؛ Moyasar توضح أن المفتاح السري قد لا يكون قابلاً للعرض مجددًا بعد إنشائه. [1]
